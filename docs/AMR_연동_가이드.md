# 실제 AMR 연동 가이드 (제어 베이스 코드 사용법)

목업은 앱 안의 **가상 AMR**(`SimulatedAmrDriver`)로 돈다. 실제 AMR을 사면 **드라이버 하나만** 바꿔 끼우면 되도록
`src/amr/` 를 나눠 두었다. 재고·화면 코드는 AMR 업체를 모른다.

```
화면(ui) ─ Controller ─ InventoryService (적재대 재고, SQLite)
                 │
                 └─ FleetManager  (작업 큐·배차·구역 잠금(도크·충전기)·자동 충전·주차·이벤트)
                        │  AmrDriver 인터페이스 (send_step / pause / resume / cancel / estop / status / poll)
                        ├─ SimulatedAmrDriver   가상 AMR (지금)
                        ├─ Vda5050Driver        VDA 5050 v2.0 (MQTT)  ← 업체가 VDA 5050 지원하면 그대로
                        └─ TcpJsonDriver        업체 고유 TCP/JSON API 템플릿 ← 복사해서 두 함수만 수정
```

## 1. 작업이 AMR에 내려가는 모양

입고 1회 = `TransportOrder` (단계 목록). 예) 사다리 3단 AMR이 박스 3개를 넣을 때

| 단계 | node | action | height_m | tray | ref |
|---|---|---|---|---|---|
| 1 | DOCK | pick | 0.85 (컨베이어 높이) | 0 | W261020-0001 |
| 2 | DOCK | pick | 0.85 | 1 | W261020-0002 |
| 3 | DOCK | pick | 0.85 | 2 | W261020-0003 |
| 4 | N03 | drop | 1.00 (3단) | 0 | N-03-3 |
| 5 | N03 | drop | 1.30 (4단) | 1 | N-03-4 |
| 6 | S02 | drop | 0.40 (1단) | 2 | S-02-1 |

FleetManager가 한 단계씩 `send_step` 으로 보내고, 드라이버가 `step_done` / `step_failed` 이벤트로 결과를 알린다.
`step.path` 는 현재 노드에서 목적 노드까지 셀 지도 경로(노드 이름 목록)다.

## 2. 설정 파일로 AMR 바꾸기 — `data\config.json`

```json
{
  "robots": [
    {"id": "AMR-01", "driver": "vda5050", "host": "192.168.0.50", "port": 1883,
     "manufacturer": "업체명", "serial": "SN0001", "interface": "uagv", "start_node": "PARK1"}
  ]
}
```

- `robots` 가 비어 있으면 가상 AMR `sim.amr_count` 대.
- `driver`: `sim` / `vda5050` (host·port = MQTT 브로커) / `tcp_json` (host·port = AMR 컨트롤러).
- 연결에 실패해도 앱은 켜지고 그 AMR은 '연결 끊김'으로 표시된다.

## 3. 셀 지도와 AMR 지도 맞추기 (가장 중요)

앱의 노드 이름(`DOCK`, `N01`..`N10`, `S01`..`S10`, `CHARGER`, `PARK1`..)이 **AMR 쪽 지도의 스테이션 이름과 같아야** 한다.
AMR 업체 지도 편집기에서 같은 이름으로 스테이션을 찍거나, 드라이버 안에 이름 변환표를 둔다.
좌표는 `src/amr/topology.py` 의 `build_cell_topology` 가 적재대 설정(열 피치 0.38 m 등)으로 만든 값이며 화면 미니맵용이다
— 실제 위치는 AMR 지도가 기준.

## 4. 업체 API가 VDA 5050이 아닐 때 — `tcp_json.py` 복사

1. `src/amr/tcp_json.py` 를 `src/amr/업체명.py` 로 복사.
2. `encode_step(step)` : 단계 → 업체 명령(JSON). 예) 이동 = 스테이션 이동 명령, pick/drop = 포크 높이 + 집기/내리기 동작.
3. `decode_message(msg)` : 업체 상태/작업 결과 → `step_done` / `step_failed` / 상태(위치·배터리·모드).
4. `src/controller.py` 의 드라이버 생성 부분에 `driver == '업체명'` 한 줄 추가.

`# TODO(업체)` 표시가 채울 곳이다. HTTP REST 나 ROS 2 라도 같은 방식으로 `AmrDriver` 를 상속하면 된다.

## 5. 어테치먼트(사다리·포크)를 직접 설계할 때

저가 AMR은 보통 **주행 베이스만** 판다. 그러면 단계 하나를 두 장치로 나눠 처리한다.

- 주행: AMR 베이스 API로 `step.node` 스테이션까지 이동.
- 집기/내리기: 직접 만든 어테치먼트 컨트롤러(PLC Modbus TCP, MCU 시리얼 등)에 "높이 h 로 승강 → 트레이 t 와 컨베이어/칸 사이 이송" 명령.

한 드라이버 클래스 안에서 "도착 확인 → 어테치먼트 동작 → 완료 확인 → step_done" 순서로 묶으면 FleetManager 는 그대로 쓸 수 있다.
어테치먼트에는 **박스 유무 센서**(포크·각 트레이)를 꼭 달고, 집은 뒤 센서가 비면 `step_failed` 로 알린다 — 재고 기록과 실물이
어긋나는 것을 막는 가장 확실한 장치다.

## 6. 저가 AMR 구매 체크리스트

| 항목 | 확인할 것 |
|---|---|
| 개방 API | VDA 5050 지원(가장 좋음) 또는 TCP/HTTP/ROS 2 API 문서 제공. "전용 관제(FMS) 필수"면 연동 불가 |
| 스테이션 이동 | 이름 있는 스테이션으로 이동 명령, 도착 정밀도(±10 mm 이하 권장, 칸 피치 380 mm) |
| 상태 보고 | 위치·배터리·주행/정지·오류를 주기적으로(1 s 이하) 보고 |
| 일시정지·취소 | 명령으로 일시정지/재개/작업 취소 가능 |
| 자동 충전 | 충전 스테이션 도킹 명령 |
| 탑재·IO | 어테치먼트 전원·IO(또는 Modbus) 제공, 가반하중 = 박스 15 kg × 3 + 어테치먼트 |
| 안전 | 레이저 스캐너 보호구역, 하드웨어 비상정지, 안전 인증(사람과 같은 통로) |
| 좁은 통로 | 셀 통로 폭 1.3 m 에서 회전 가능 크기 |

## 7. 시험 순서 (실기)

1. 앱은 가상 AMR로 그대로 두고, 업체 시험 도구로 AMR이 스테이션 이름대로 움직이는지 확인.
2. 드라이버만 연결해서 **이동 단계만** (action none) 보내 보기 — 미니맵 위치·배터리 표시 확인.
3. 빈 트레이로 pick/drop 동작만 시험 (박스 없이).
4. 박스 1개 입고 → 적재대 칸 기록과 실물 일치 확인. 이후 3개 묶음, 연속 운전.
5. 2대 이상 운전 전에 통로 교통 제어(노드·구간 예약)를 추가한다 — 지금은 도크·충전기 잠금만 있다.

> 앱의 [비상정지] 버튼은 작업을 멈추는 **운영 기능**이지 안전 기능이 아니다. 사람 보호는 AMR 자체 안전장치와 하드웨어 비상정지로 한다.

## 8. 남은 일 (실기 전)

- 통로 교통 제어 (2대 이상), 단계 시간 초과 감시(응답 없는 AMR 알림), AMR 쪽 지도 이름 변환표.
- 실제 박스 ID 체계 결정 (바코드/RFID 라벨이 박스마다 고정인지, 채울 때마다 새 번호인지).
